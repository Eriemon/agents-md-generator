# Evaluation Scenarios

Use these scenarios to forward-test the skill after changes.

Coverage mapping rule:
- `skills/agents-md-generator/evals/evals.json` is for with-skill versus without-skill comparisons and other explicit effectiveness proofs.
- Python regression coverage lives under the matching `tests/<feature>/` package and does not use root-level test modules.
- manual governance gates are reserved for workspace-specific branch, release-artifact, install, and confidence checks whose truth depends on real repository state.

| Scenario | Expected result |
|----------|-----------------|
| Minimal project | Generates concise AGENTS.md without inventing commands or frameworks |
| TypeScript package | Detects package manager, scripts, test runner, and package.json source |
| Python project | Detects pyproject.toml, ruff/mypy/pytest where configured |
| Go project | Detects go.mod and suggests gofmt, go test, go build |
| PHP project | Detects composer scripts and framework hints |
| Hybrid project | Keeps root thin and avoids mixing frontend/backend commands |
| Existing AGENTS.md | Preserves hand-written content outside generated markers |
| AGENTS.md compression | Root generated `AGENTS.md` stays within 20KB, scoped AGENTS files are not blocked by the old line rule, and over-limit root manual content blocks writes |
| Outdated AGENTS.md | Reports freshness risk from git history |
| Scoped directories | Creates scoped files only for distinct local rules |
| Cross-agent shims | Creates CLAUDE.md/GEMINI.md without overwriting existing non-managed files |
| Docs governance | Strong-control generation creates `docs/handoff/HANDOFF.md`, archives old handoffs under `history_handoff`, records development stages, and leaves legacy `docs/experience/` data unmanaged |
| Optional document registration | The document registry is skipped without an explicit user request and creates no state; explicit opt-in scans only `SKILL.md` and `references/**/*.md`, requires unique document responsibilities, governed duplicate and interface decisions, current Markdown hashes, and user confirmation only for uncertain adjudications before finalization |
| Memory governance gate | Strong-control work folders require enabled `docs/memory`; `memory-gate` blocks missing/disabled/corrupt memory and reports an authorization command, `memory-init --confirm-create` creates the store, exact-cwd Codex sessions bootstrap into ordered timestamped summaries, and verify/work-folder gates fail when memory is unbootstrapped |
| OpenAI metadata standard contract | `short_description` stays within 25–64 characters; `default_prompt` stays within 256 UTF-8 bytes, is one sentence, starts with `Use $agents-md-generator`, and leaves detailed governance policy in `SKILL.md` and references |
| Handoff naming gate | Renaming `docs/handoff/HANDOFF.md` or introducing non-standard history archive names causes `scaffold`, `verify`, work-folder/release gates, and confidence-sensitive flows to fail until `repair-handoff-names --write` repairs the governed names |
| Workspace settings gate | Strong-control generation documents `.settings/project.local.json` and `.settings/project.remote.json`, structure governance rejects workspace config json outside `.settings/`, and remote review blocks all `.settings/*.local.json` such as `.settings/server_list.local.json` |
| Codebase memory MCP gate | Every generation/update explicitly asks `use_codebase_memory_mcp`; missing enabled dependencies produce official manual-install guidance; enabled writes require root-only full persistent indexing, ready architecture analysis and matching live/disk counts; disabled writes skip MCP access; tracked artifacts require confirmation before index-only removal |
| Compact root remote contract | Remote-enabled generation keeps full server registry and task routes in `.agents/agents-control.json`, while root `AGENTS.md` only points to that source, keeps fallback/unmatched-task gates, and avoids server names, functions, runners, and absolute remote paths |
| Experience removed | `v1.1.0` removes experience governance: `manage_docs.py experience` and `bootstrap-experience` return `invalid choice`, the fifth handoff does not create `.agents/experience-update-request.json`, verify ignores missing or stale `docs/experience/`, and memory still records handoff context |
| Evolution removed | `v1.0.0` removes the evolution subsystem: no `manage_docs.py evolve`, no `import-evolution`, no tenth-handoff atomic evolution contract, no template sink/export/import flow, and mutating docs-governance commands clear legacy evolution state and assets |
| Skill effectiveness evals | `python skills/agents-md-generator/scripts/python/verify/run_skill_evals.py skills/agents-md-generator/evals/evals.json` reports with-skill versus without-skill deltas, recent high-risk regressions, machine-readable case summaries, all five Skill design patterns, and installable eval-runtime boundaries; `python tests/evaluation/run_skill_evals.py ...` remains a compatibility wrapper |
| Language skill routing contract | `language_skill_routing_contract` proves `coding_behavior.language_skill_routing` has exactly `shared`, `python`, and `script`; the shared think-first and process-time gate is 只渲染一次; Python/script routes exclude that shared body and keep their own scope, owner, and cross-language boundaries; all four skill-installation states render honestly; legacy two-field wording is accepted only in legacy mode; and strict `verify_agents.py` rejects missing, repeated, or weakened routing |
| Script output policy contract | `script_output_policy_contract` proves generated root AGENTS.md includes `## Script Output Policy`, writes configurable `script_output_policy` with config-driven Kind values, requires strict `> INFO: [{kind}]` / `> WARNING: [{kind}]` / `> ERR: [{kind}]` formats, and makes `verify_agents.py` reject missing or weakened output policy |
| Plan Mode language lock contract | `plan_mode_language_lock_contract` proves the default-language rule also covers Plan Mode `<proposed_plan>` body text, and `verify_agents.py` rejects managed roots that keep only the generic reply-language rule without the Plan Mode lock |
| Version semantics split | When installed `agents-md-generator` version and target project skill `VERSION` differ, `sync-root-agents` still reports clean root metadata if metadata matches the generator version, while `version_alignment_gate` and `verify_agents.py` still enforce the project version only on Control Profile and release-doc records |
| Governance review gate | `review_governance.py` detects governance-sensitive script, CLI, gate, eval, checklist, and version-release documentation drift; non-release modes emit `review_dispatch_policy=optional|none`, `--mode release` emits `required_for_release`, and `work-folder-gate` aggregates resume, structure, dir-manager, branch, version, and freshness checks before confidence-sensitive work |
| Governance runtime de-vendoring | External workspaces render governance commands through the installed `agents-md-generator` runtime such as `python <codex-home>/skills/agents-md-generator/scripts/python/docs/manage_docs.py ...`, and `verify_agents.py` rejects project-local commands like `python scripts/manage_docs.py ...` or `python skills/<project-skill>/scripts/manage_docs.py ...` |
| Task rating gate contract | `task_rating_gate_contract` proves the global v3 baseline prefers reuse first, carries `Coding Behavior Baseline` with lightweight `readable-python-generator` / `readable-script-generator` routing, carries `Comments And Documentation` without skill-selection rules, includes environment/dependency safety requiring isolated environments for risky Python work, installed skill protection, Markdown documentation formulas, and repository governance boundaries; it also proves the gate does not ask difficulty/scale for every task, asks when complex or unclear work needs rating confirmation, preserves explicit/contextual hell or nightmare ratings without re-asking, and does not misread a difficulty-order list as a user rating |
| Design review hard gate | `collect_design_profile.py --write` rejects aligned answers until `extra_requirements` is explicit and a new subagent `design_review` approves the full answers/profile with matching hashes; `--intent read_only` must stop at `completed_read_only` without a reviewer, and `--enter-write-review` is required before that same interview can enter subagent review |
| Missing root routing effectiveness | With-skill detects missing root `AGENTS.md` and emits rebuild-required routing; without-skill baseline lacks that structured trigger behavior |
| Takeover routing effectiveness | With-skill routes version-mismatched landed workspaces into takeover mode; without-skill baseline does not distinguish the compatibility path |
| Root whitelist gate effectiveness | With-skill blocks unexpected root drift and requires structure-fix confirmation; without-skill baseline leaves the repository ungoverned |
| Additional worktree prohibition | `additional_worktree_prohibition_contract` proves linked or additional registered worktrees and reserved worktree container directories are hard-blocked before profile, render, release, package, or install side effects; confirmation and disabled Git management cannot bypass the policy |
| Workspace boundary double confirmation | `workspace_boundary_double_confirmation` proves every managed root renders one complete boundary; urgent external writes, blanket approval, and first-confirmation-only states still stop; external reads remain necessary and side-effect free; target or scope changes invalidate both confirmations; weakened and duplicate rules fail strict verification |
| Root workspace artifact gate | With-skill allows root `tests/`, `smoke*`, `reports/`, and `runs/`, but blocks the same directories when nested under `skills/<skill-name>/...` or `engineering/<project-name>/...`; without-skill baseline does not enforce that boundary |
| Generic audit/evaluate effectiveness | With-skill allows generic target skills to pass core audit checks while still preserving self-skill hardening, and generic evaluate reports machine-readable failure categories instead of only flat error strings |
| Source governance test boundary | `source_governance_test_boundary` proves the formal eval runner and runtime helper live under `scripts/python/verify/`, the `tests/evaluation/run_skill_evals.py` path is only a wrapper, stale `tests/eval_fixtures.py` is not required, and source-governance gates still block true test-only fixtures outside tests |
| Source governance size and readability | `source_governance_size_readability_contract` proves governed source is measured by the 64KB UTF-8 byte limit, oversized files need a valid decomposition plan, excluded roots such as `tests/` stay skipped, and one-line compressed or minified unreadable source is blocked |
| File naming and semantic review | Source governance rejects digits, leading underscores, nonfunctional characters, and stems over 30 characters except `__init__.py`; review governance separately rejects missing, stale, incomplete, or failed Agent semantic-review evidence for changed functional source and Python tests |
| Root tests feature layout | Directory structure governance requires exactly one root `tests/`, permits only `tests/__init__.py` as root Python, requires one-level `tests/<feature>/*.py` grouping, and rejects nested `tests/` directories |
| Readability-only runtime decomposition | Internal helper extraction in CLI, gate, docs-sync, or runtime-routing modules preserves command arguments, exit codes, JSON fields and ordering, routing decisions, and write boundaries; managed language-route refresh still migrates the complete default set while preserving customized values; focused unittest coverage and the existing source-governance, root-version-sync, language-routing, and formal 29-case eval contracts remain green |
| Release completeness effectiveness | With-skill install validation rejects releases whose `SKILL.md` references missing formal settings/content resources such as `assets/defaults.json` or `config/defaults.json`; without-skill baseline only validates receipt shape and can miss the gap |
| Release sanitizer regex constants | `package-release` preserves Python regex constants such as `SECRET_RE = re.compile(...)`, still redacts real token/password assignments in non-code release text, records sanitization evidence in `RELEASE_RECEIPT.json`, and leaves dist scripts compilable |
| Install replacement cleanup | Replacing an installed skill removes any legacy `assets/templates/evolution/` content instead of preserving, merging, or exporting retired template assets |
| interrupted session | `start-session` creates an active session, `resume-check` detects an unchanged HANDOFF.md after interruption, and `resume-repair` writes a recovery handoff |
| Directory governance | Strong-control generation creates `docs/dir_manager/`; planned local and remote deployment directory changes are governed, unsafe top-level, governance, or project-outside path changes are blocked, remote deployments do not sync local skill-development content by default, and force-confirmed blocked changes archive old dir manager content under `history_dir_manager/<timestamp>/` |
| Release install confirmation | After validation, only skill-development release flows ask about `install_skill.py`; engineering releases do not prompt for skill installation |
| Release content policy | `package-release`, `release-gate`, and `install_skill.py` allow governed skill-local `evals/` plus formal eval runner/helper files in installable dist releases, reject `tests/`, `test/`, `smoke*`, `_smoke_runs/`, `reports/`, `runs/`, and cache artifacts, and record machine-readable `release_content_policy` evidence in receipts |
| Old workspace takeover | A landed workspace with missing or stale root `AGENTS.md` enters takeover mode, asks only for minimal identity fields, generates a strong-control profile, and then uses forced local directory takeover instead of a full design interview |
| Bad paths | Verification reports missing or suspicious path references |
| Placeholder leak | Verification reports unresolved `{{PLACEHOLDER}}` tokens |
